0. HOW THIS AUDIT WAS DONE
--------------------------------------------------------------------------------
Method: nine read-only audit agents were given exclusive file ownership over
each attack surface (Electron IPC/bridge, workspace file IO, agent tool loop,
terminal + shell integration, preview/dev-server runtime, MCP, secrets/vault +
build/bundle, API backend + SSRF + metering, release/updater/supply chain).
Each returned findings with file:line evidence. I then independently
re-verified every Critical and High claim myself with Read/Grep/Bash and, where
possible, runtime checks (curl against GitHub Releases, grep for renderer HTML
sinks, grep for CSP headers).

Rules respected: no code was changed; .env, node_modules/, dist/, landing/out/,
package-lock.json were not read; reference/zed-main and reference/void-main were
not read or copied; no secret values are reproduced in this file.

Label legend:
  [V]    verified by me directly (file:line confirmed in this session)
  [VR]   verified by runtime observation (a command was executed)
  [A]    reported by an audit lens, plausible, but I did not re-open the file

Threat model (what we assume is hostile):
  T1  The project folder the user opens (package.json scripts, conftest.py,
      .git/config, .shadrox/* config files, planted git.exe/npm.cmd shims,
      symlinks/hardlinks, AGENTS.md and skill files).
  T2  Model output (tool arguments, patch bodies, confirm flags, display
      strings, "please run this command").
  T3  A website shown in the preview pane / opened in a browser window.
  T4  A malicious MCP server or a malicious MCP tool result.
  T5  A compromised or buggy update channel / release artifact.
  T6  Renderer XSS escalating into the desktop IPC bridge.
  T7  Prompt injection steering the agent toward real-world effects.

Bottom line: ShadRox has genuinely strong *plumbing* (path confinement, frame
trust, git SCM hardening, secret storage, proof signing) but the *policy* layer
around code execution is weak in exactly the places a hostile project folder
reaches first. Three Criticals are all T1→RCE and all reduce to the same
sentence: "opening a folder runs that folder's code without asking."

Score: 3 Critical, 8 High, ~20 Medium, several Low. Ranked fix order in §5.

1. CRITICAL

C1. The "verify" allowlist silently executes untrusted repository code.  [V]
--------------------------------------------------------------------------------
Evidence
  electron/verify-allowlist.cjs:56-63
      VERIFY_ALLOWLIST = npm:[['test']], pytest:[[]], python:[['-m','pytest']],
                         tsc:[['--noEmit']], npx:[['tsc','--noEmit']],
                         git:[['diff'],['status']]
  electron/command-approval.cjs:14-21  isAllowedVerifyCommand(argv)
  electron/command-approval.cjs:47      cwd = path.resolve(workspace.root)
  electron/command-approval.cjs:51-58   allowlist hit => no dialog at all
  electron/command-approval.cjs:72      result: await runCommand(command, cwd)
  electron/main.cjs:838-856             runCommand uses exec(command, {cwd,
                                        timeout:120000, env: agent terminal env})

Attack path (T1)
  `npm test` executes the repository's own "test" script — arbitrary JS.
  `pytest` / `python -m pytest` imports conftest.py and test_*.py — arbitrary
  Python, at import time, before any test runs.
  `npx tsc --noEmit` resolves from the workspace's node_modules/.bin first —
  arbitrary JS from a planted package.
  The agent does not need approval for any of these, so a single poisoned
  README instruction ("run npm test to see the problem") is enough for silent
  code execution with the user's desktop session, env, and keychain access.

Aggravating factor: the defences written for this exact scenario are dead code.
  verify-allowlist.cjs:157 resolveExecArgv() and :174 findPlantedShim() are
  referenced only from verify-allowlist.cjs, command-approval.cjs and their
  *.test.cjs files. [V — grep across the repo finds no production caller.]
  So a shim planted as `node_modules/.bin/git.exe` or a `npm.cmd` next to the
  cwd is never checked, even though the check exists and is unit-tested.

Fix (small–medium, ~1–2 days)
  1. Default-deny by *content*, not by argv shape. Replace the six allowlist
     entries with: any command whose effect is "run repo code" requires the
     native dialog. Keep only read-only, non-repo-dependent commands (e.g.
     `git diff`/`git status` confined as in C3).
  2. Wire the hardened helpers that already exist: resolveExecArgv +
     findPlantedShim must run on the real spawn path, and PATH must be rebuilt
     from a trusted prefix that excludes the workspace and node_modules/.bin.
  3. Replace exec(string) with spawn(argv, {shell:false}) so
     SHELL_METACHARACTERS (verify-allowlist.cjs:46) stops being the only
     barrier between `npm test` and `npm test && powershell -enc …`.
     Note :72 passes a raw string into exec() after the argv check — the
     check and the execution are not over the same representation.
  4. Run pytest/npm with --no-* / isolated flags where possible, and never
     with the user's HOME-level config.

C2. Opening a folder silently installs dependencies and starts the dev server. [V]
--------------------------------------------------------------------------------
Evidence
  src/App.tsx:1186-1195   auto-approves the preview, comment reads
                         "opening a folder already implies consent to run it"
  src/App.tsx:1237-1249   750 ms timer then auto-starts
  electron/main.cjs:2148-2180 preview:start handler — an "approval required"
                         payload (manifestHash, scriptCommand,
                         missingDependencies) is built and returned to the
                         renderer, but the status text sent to the UI is
                         "Starting automatically."; the handler then calls
                         previewRuntime.start at :2180.
  electron/preview-runtime.cjs:955-959 and :1026 [A] — npm install + the
                         package's own dev script are executed.

Attack path (T1, T7)
  npm install executes preinstall/postinstall of any dependency, i.e. arbitrary
  code from the registry chosen by the repo's package.json. This happens with
  no native dialog, within ~1 second of the folder being opened. It also
  contradicts the product's own landing copy ("ShadRox asks before installing")
  — a truth-in-advertising exposure on top of the security one.

Fix (small, ~1 day)
  Move the decision to the main process: preview:start must show the native
  Electron dialog for install/dev-script and block until answered. Delete the
  renderer-side auto-approve at App.tsx:1186-1195; the 750 ms timer may only
  start a preview that was already approved for that workspace root, and
  re-approval must trigger when package.json's hash changes (the manifestHash
  recheck at main.cjs:2173 already computes this — it is informational only).

C3. Allowlisted `git status` / `git diff` are executed through cmd.exe with
    the user's own git config and a cwd-first PATH.                   [V]
--------------------------------------------------------------------------------
Evidence
  verify-allowlist.cjs:56-63 allows git diff / git status without approval.
  command-approval.cjs:72 → main.cjs:838-856 → exec() (Windows: cmd.exe /d /s
  /c), cwd = workspace root.
  The hardened path exists but is used only by the SCM bridge:
  main.cjs:890-891 is the only caller of resolveGitExecutable() /
  buildIsolatedGitEnv() [V — grep]. Those helpers set core.hooksPath, disable
  fsmonitor, refuse filter drivers, and pin an absolute trusted git.exe.
  The agent command path uses none of it.
  electron/main.cjs:904-944 gitSafetyContext/requireGitWorkspace [V] does not
  confine the .git directory itself to the workspace.

Attack path (T1)
  (a) Hostile .git/config: `core.fsmonitor = <cmd>`, `core.pager = <cmd>`,
      `core.hooksPath = <dir>` — `git status`/`git diff` spawn it.
  (b) Planted `git.exe` / `git.cmd` at the workspace root or in
      node_modules/.bin: with cmd.exe + cwd-first resolution, that binary runs.
  Both are silent because these two argv shapes are on the no-dialog list.

Fix (small, ~0.5–1 day)
  Route *every* git invocation — including the agent's — through
  resolveGitExecutable + buildIsolatedGitEnv, and spawn argv with shell:false.
  Add `git -c core.fsmonitor= -c core.hooksPath=.git/hooks -c core.pager=`
  explicitly and refuse repos whose gitdir resolves outside the workspace.
  Same treatment for npm/npx/pytest as C1.

2. HIGH

H1. No Content-Security-Policy anywhere in the packaged app.          [V]
--------------------------------------------------------------------------------
Evidence: index.html has no CSP meta; server.ts sets no CSP header; main.cjs
has no onHeadersReceived CSP rule. The renderer exposes desktop.* including
secure:get-all (main.cjs:1100-1114) and terminal write.
Grep confirms zero dangerouslySetInnerHTML / .innerHTML / insertAdjacentHTML /
outerHTML / eval( / new Function( in src/ [V] — the renderer builds markdown as
a React AST and only allows http(s) links, which is why this is High and not
Critical today.
Risk: any future DOM sink, any third-party script in a previewed page reaching a
messaging surface, or a devtools-era bug becomes full bridge access.
Fix (small, ~0.5 day): default-src 'none'; script-src 'self'; style-src
'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'
ws://127.0.0.1:* http://127.0.0.1:* https:; frame-src (none for the app
document); plus a main-process onHeadersReceived rule for every file:// window.

H2. Saving an MCP server connects and spawns it with no native consent. [V]
--------------------------------------------------------------------------------
Evidence: electron/main.cjs:2500-2526 — mcp:save-server and mcp:connect do
assertTrustedRenderer and then return; no dialog, no confirmation of the
command. mcp-client.cjs:216 [A] spawns the configured command/args directly.
The renderer can be steered by model output (an agent that "sets up a
connector for you"), so T2 → T4 → arbitrary process spawn.
Good news: tool *calls* do raise the native dialog, .cmd/.bat are refused, and
MCP config only lives in userData (never workspace-declared). [V]
Fix (small, ~0.5 day): confirm command + args in the main process on first
spawn per server id, remember the decision keyed by a hash of the command line.

H3. Debug host: no consent, unsanitised adapter args, hostile adapter, full env.
--------------------------------------------------------------------------------
Evidence [V]
  electron/debug-host.cjs:115-148 resolveAdapterCommand — an absolute path
      outside the workspace is accepted (:126); the js-debug-adapter fallback
      resolves from the workspace's own node_modules (:135-138).
  electron/debug-host.cjs:151-165 resolveAdapterArgs — `if (arg.startsWith('-'))
      return arg;` (:153) passes any flag verbatim; non-.js files pass through
      (:163).
  electron/debug-host.cjs:726-732 spawn(..., {cwd, env: process.env,
      shell:false}) — the whole desktop environment, including any secret that
      lives in env, is handed to a process chosen by the workspace.
  No native approval dialog exists on the debug:start path (renderer-mediated).
Fix (medium, ~1–2 days): native consent on first adapter per workspace; allow
only a small flag allowlist; require the adapter to be either ShadRox's own
bundled one or a user-picked path stored in userData; scrub env with the same
credential filter used for terminals.

H4. Vault secrets are compiled into the preview bundle that runs attacker code.
--------------------------------------------------------------------------------
Evidence [V] src/lib/bundler.ts:710-730
  secrets.forEach(s => { define['process.env.'+s.key] = JSON.stringify(s.value) })
  viteEnv[s.key] = s.value;  define['import.meta.env'] = JSON.stringify(viteEnv)
Combined with C2, the built artifact embeds cleartext API keys into a bundle for
a project that can execute arbitrary code and read its own build output. Keys
also end up in any dist/ the user later commits or shares.
Fix (small, ~0.5 day): never inline secret *values* into a user-project build.
Provide a dev-server proxy that injects headers, or require explicit per-key
opt-in with a visible warning in the UI. [VR for the esbuild define reachability
— the generated artifact was not inspected; still, the values are in the JS.]

H5. Rules / AGENTS.md / skill metadata are injected raw into system
    instructions, while permissionMode defaults to "agent" and auto-apply
    defaults ON.
--------------------------------------------------------------------------------
Evidence [V]
  src/lib/agent/rules.ts:281 and :300 append rule bodies without
  markUntrustedData; src/App.tsx:1881 and :1883 [A] inject skill descriptions
  the same way.
  src/App.tsx:515-522 permissionMode default = 'agent'.
  src/App.tsx:550-556 autoApplyChanges = localStorage !== 'off' → default ON,
      and the catch branch returns true.
Contrast: the codebase already has markUntrustedData / scrubWorkspaceText and
uses them on file content — the rules path simply skips them.
Fix (small, ~0.5 day): wrap every injected rule/skill string with the existing
untrusted-data marker; make autoApplyChanges default OFF and fail closed; show
"this project supplied instructions" in the UI so the user can see the
influence.

H6. The signed proof ledger stores raw, unredacted command output outside the
    workspace.
--------------------------------------------------------------------------------
Evidence [V]
  src/lib/agent/tools.ts:543-558 receipt target = the command string,
      errorMessage = stderr||stdout, stackTrace = (stdout+stderr).slice(0,4000).
  electron/proof-service.cjs:57-105 normalizeReceipt only clipUtf8()s —
      target 4096, errorMessage 8192, CONDITIONAL_KEYS 16384, diffSummary 4096,
      relevantFiles 64×512. No redaction call.
  main.cjs:334 is the sole redactCommandForProof call site [V] — redaction
      exists but is not applied to the payload that actually leaves.
Result: a token printed by a failing command (very common: test harnesses echo
env) is signed and written to a user-level ledger that is later shared/screenshot
when the user asks for help.
Fix (small, ~0.5 day): run every receipt field through the existing redaction
before normalizeReceipt; add a second pass on diffSummary and relevantFiles.
Note the pattern set itself is weak — see M6.

H7. The Git directory is never confined to the workspace.             [V]
--------------------------------------------------------------------------------
Evidence: main.cjs:904-944 gitSafetyContext / requireGitWorkspace resolve the
repo from the workspace root with git plumbing but never compare the resolved
gitdir against the workspace.
Impact: a planted `.git` symlink or a `.git` file with `gitdir: C:/Users/…`
makes every SCM read (status/diff/log) operate on a repository the user never
opened; a 60,000-line diff is then uploaded for commit-message generation
(§M12), leaking another project's content.
Fix (small, ~0.5 day): realpath the gitdir and refuse when it escapes the
workspace root; reuse the per-component lstat logic from confinement.ts.

H8. Update channel: unsigned Windows artifacts + autoDownload +
    autoInstallOnAppQuit — and currently broken anyway.                [VR]
--------------------------------------------------------------------------------
Evidence
  electron/updater.cjs:37-38 / :62 [A] autoDownload and
      autoInstallOnAppQuit enabled.
  package.json win block: no signing config found [V — grep for cscAuth/
      certificateFile returns nothing].
  Runtime: https://github.com/…/releases/latest/download/latest.yml → 404;
      the v0.0.7 release contains only ShadRox-v0.0.7-Setup.exe.
Two separate problems: (a) an attacker who can write the Releases feed or do
MITM on a non-HTTPS path gets code execution at quit without user action;
(b) delta updates silently do not work today, so users stay on old builds and
re-download installers from a page anyone can edit.
Fix (small–medium, ~1–2 days): Authenticode-sign build + updater artifacts,
verify SHA-512 before install, disable autoInstallOnAppQuit until signed, and
add a CI step that publishes latest.yml next to the Setup.exe.

3. MEDIUM
================================================================================
M1. SSRF vetting is lexical only. [V]
    api/ai/_endpoint.ts:96-131 checks scheme, userinfo, query, host shape; then
    :117 `if (runsOnTheUsersMachine()) return …` short-circuits BEFORE the https
    requirement (:121), the hostname blocklist (:124) and
    :127 isIpAddress(host) && isBlockedAddress(host). Hostnames are never
    resolved, so `dns.rebinding.attacker.tld` → 169.254.169.254 passes;
    redirects are followed by the fetch layer (api/ai/_upstream.ts:101 [A]).
    Fix: resolve → pin IP → validate → connect to that IP; re-validate each
    redirect hop; remove the local-run early return from the deny checks.
    ~2 days.

M2. Admission/spend guard is wired to one endpoint only. [V]
    checkAdmission appears at api/ai/_spendGuard.ts:193 and api/ai/chat.ts:168.
    fim, commit-message and refine share the upstream path but never call it →
    they fail open for metering. Related: _spendGuard.ts:76-81 trusts
    X-Forwarded-For for the process-local brake [A], which is attacker-supplied
    on Vercel. Fix: put admission in the shared upstream helper; derive the
    "local" decision from a signed main-process handshake, not a header. ~1 day.

M3. .env content is searchable and previewable even though readFile refuses it.
    [V] electron/workspace.cjs:747 carves .env out of the search/read refusal.
    Fix: exclude dot-env family from search results and previews; allow an
    explicit, dialog-gated "show secret file". ~0.5 day.

M4. Agent-writable main-side config. [V]
    workspace.cjs:77 SHADROX_CONFIG_PATTERN is also the write allow-list, and
    :837 lets a config-matched path be written even when it is not in
    fileMap; a test asserts .shadrox/automations.json and plugin.json are
    writable. Protection for these lives only in the renderer
    (applyPolicy.ts:66-80, confinement.ts:33). Writing automations.json =
    scheduling commands with a webhook. Fix: main-process deny-list for
    execution-affecting config; writes there require a native dialog. ~1 day.

M5. Hardlink check missing on the ordinary read path. [A]
    The machine-delta path checks nlink>1; the read path does not, so
    `note.txt -> /c/Users/<user>/.ssh/id_rsa` reads through confinement.
    Fix: same nlink + realpath check in readFile. ~0.5 day. [needs runtime
    verification on OneDrive placeholders — see §6.]

M6. Redaction patterns miss common credential shapes. [V for pattern set]
    Missing: Stripe sk_live_/sk_test_, GitLab glpat-, npm npm_, Google ya29.,
    JWT (eyJ…Header.Payload.sig), PEM blocks, bare `Bearer <token>`, and
    camelCase JSON keys (apiKey, clientId) in the JSON-key matcher.
    Fix: extend the patterns; add entropy-based detection for the ledger. ~1 day.

M7. Two divergent env scrubbers and one that uses neither. [V]
    terminal-modes.cjs filters by key name only; envSafety.cjs filters by
    name+value shape; debug-host.cjs:731 passes process.env raw (see H3).
    Fix: one shared scrubber, used by terminal, agent exec, preview and DAP.
    ~1 day.

M8. Terminal is a two-way channel into the pty. [V]
    src/components/TerminalPanel.tsx:143-155 writes raw output into xterm;
    :167-171 forwards terminal.onData → desktop.writeTerminal. Output from an
    attacker-controlled program can drive emulator-generated replies (DCS/CSI
    queries) back into stdin.
    Also: electron/shell-integration/shadrox.sh:11 emits `$BASH_COMMAND` into
    an OSC 633 payload without stripping control bytes, while shadrox.ps1:34
    does strip ([\r\n\a\Esc]) [V].
    Fix: neutralise OSC/DCS reply generation, sanitize the bash integration
    payload like the PowerShell one, and gate writeTerminal in main with the
    same printable-only rules already used for terminal_answer. ~1 day.

M9. Consent UIs render model-controlled strings without visual neutralisation.
    [V] src/components/ChatPanel.tsx:690-703 renders command/file names as
    received. injectStdin.ts:80-95 already proves the pattern (bidi, zero-width,
    homoglyph stripping) elsewhere in the codebase.
    Fix: reuse it in every dialog/panel that shows a target path or command.
    ~0.5 day.

M10. delete_file's confirm flag comes from the model. [V]
    src/lib/agent/tools.ts:465-493 refuses unless asBoolean(call.args.confirm)
    === true, then calls desktop.deletePath — no main-process gate. Deletion is
    not reversible, and T2 controls the flag. Note main.cjs:1934-1937 delete-path
    handler itself performs no approval [V].
    Fix: native confirm in main for deletes outside the fileMap or of
    execution-affecting files; never trust an argument as consent. ~1 day.

M11. RunPolicy scope/limits are not populated by any caller. [V]
    src/lib/agent/runPolicy.ts is genuinely integrated now — toolLoop.ts:8/83/
    268 calls allowsEffect(policy.mode, effect), turnRunner.ts:28/84/389 gates
    writes, turnRunner.ts:232-234 consumes scope.allowedPaths, and
    runPolicy.test.ts exists. But the read caps (maxRead*) and a real allowed
    path list are only defaults; no caller builds them per turn.
    Fix: build scope from the user's request; enforce read caps in the tool
    loop. ~2 days.

M12. GitHub push uploads editor buffers with no secret denylist; create-repo
    defaults to public. [A] api/…/push.ts:49, create-repo.ts:38.
    Fix: refuse to stage .env*/key material, default repo visibility private,
    show a file list in the native dialog. ~1 day.

M13. Dev backend binds 0.0.0.0 and SHADROX_LOCAL_BACKEND=1 disables SSRF, tier
    and admission checks. [V] server.ts:74-102.
    Fix: always bind 127.0.0.1; make the local assertion a signed token from the
    main process, and never let an env flag remove security checks. ~0.5 day.

M14. Packaged backend reads .env from an unpinned cwd. [V] server.ts:19
    dotenv.config(), main.cjs:804-836 [A] chooses the launch cwd.
    Fix: pass the intended path explicitly or drop dotenv in the packaged app.
    ~0.5 day.

M15. blob: windows are allowed unconditionally. [V] main.cjs:2770-2774
    `if (url.startsWith('blob:')) return { action: 'allow' }`.
    Fix: allow only for the window that created it. ~0.5 day.

M16. Loopback certificate errors are accepted for the default session. [V]
    main.cjs:288-305 — the rule is scoped to loopback hosts but applies to the
    whole session, so a proxy that terminates TLS at 127.0.0.1 gets a pass.
    Fix: install the listener on the preview webcontents only. ~0.5 day.

M17. Chat transcripts persist unencrypted and unscrubbed in localStorage. [A]
    src/lib/chatHistory.ts:99-175. Paste-a-key-into-chat survives logout and is
    plaintext on disk. Fix: run the M6 redactor on persistence, or store in
    safeStorage. ~1 day.

M18. Second instance argv opens a folder and grants consent. [V]
    main.cjs:2669-2700 handles the CLI argv path, :1731-1748 grants workspace
    consent. A "Open with ShadRox" from a hostile archive flow auto-consents.
    Fix: re-confirm on second-instance open. ~0.5 day.

M19. Dead code that gives a false sense of protection. [V]
    src/lib/agent/commandGuard.ts (~512 lines) is not on the live path;
    findPlantedShim/resolveExecArgv are test-only (see C1). Either wire them or
    delete them — commented intent plus an unused function is worse than
    neither. ~0.5 day.

M20. Preview docs load cdn.tailwindcss.com [A] — an unpinned third-party script
    inside the pane that is used for approval UI. Fix: vendor it. ~0.25 day.

5. RANKED FIX ROADMAP
================================================================================
P0 — closes silent remote-code-execution from a project folder (≈4 days)
  1. Kill the repo-executing allowlist entries; use spawn(argv, shell:false)
     and native dialogs.  (C1)
  2. Wire resolveExecArgv + findPlantedShim + a PATH that excludes the
     workspace and node_modules/.bin on every agent command.  (C1, M19)
  3. Route every git call through resolveGitExecutable + buildIsolatedGitEnv;
     confine the gitdir.  (C3, H7)
  4. Make preview install/start require a main-process dialog; remove the
     renderer auto-approve and the 750 ms auto-start without prior approval.
     (C2)

P1 — closes escalation, leakage and consent bypasses (≈5 days)
  5. CSP in index.html + onHeadersReceived for all windows.  (H1)
  6. Native consent for MCP save/connect and debug:start; adapter allowlist;
     scrub DAP env; one shared env scrubber everywhere.  (H2, H3, M7)
  7. Stop inlining vault secrets into user bundles.  (H4)
  8. Wrap rules/skills as untrusted; auto-apply default OFF + fail closed. (H5)
  9. Redact the proof ledger before signing; extend the credential patterns.
     (H6, M6)
 10. Native delete confirm; main-side protection for execution-affecting
     config; drop the .env search carve-out.  (M10, M4, M3)

P2 — backend, distribution and polish (≈6 days)
 11. SSRF: resolve → pin → validate → connect; revalidate redirects; remove
     the runsOnTheUsersMachine() early return from the deny checks.  (M1)
 12. checkAdmission on every shared-spend endpoint; signed local assertion
     instead of XFF.  (M2, M13)
 13. Update channel: Authenticode signing, latest.yml in CI, disable
     autoInstallOnAppQuit until signed.  (H8)
 14. Terminal hardening (reply generation, OSC sanitisation, main-side write
     gate), visual neutralisation in consent UIs, blob:/cert scoping, second
     instance re-confirm, transcript redaction, npm ci, fuses.
     (M8, M9, M15, M16, M18, M17, L1, L2)
 15. Populate RunPolicy scope and enforce read caps; delete or wire
     commandGuard.ts.  (M11, M19)

Rule of thumb for sequencing: anything that decides whether code runs must be
enforced in the main process. Today most of those decisions are made in React
state, which model output can influence, which is why C1/C2/C3 and H2/H3/H5/H10
are the same bug seen from different angles.

9. ONE-PARAGRAPH SUMMARY
================================================================================
ShadRox's low-level file, path, IPC-trust and crypto plumbing is better than
most indie Electron tools — per-segment symlink confinement, two-layer frame
trust, a fail-closed git hardening helper set, safeStorage secrets and a signed
proof ledger. The security failure is at the policy layer: the default-deny
command gate has six allowlist entries that all run repository code (C1), two
of those run through cmd.exe with the user's own git config and a
workspace-first PATH (C3), opening a folder silently installs dependencies and
starts the dev server (C2), and the hardened exec/git helpers that would fix
both are written but never called. On top of that there is no CSP (H1), MCP and
debug spawn without native consent (H2, H3), vault secrets are compiled into
the bundle that runs attacker code (H4), project-supplied instructions enter
system prompts unwrapped while agent mode and auto-apply default to "yes" (H5),
and the signed ledger records unredacted command output (H6). Fix P0 first — it
is about four days of work and removes every silent RCE-from-folder-open path
found in this audit.
