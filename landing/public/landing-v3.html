How it works

From folder to commit,
in three steps.

Open a local folder, choose your AI provider, and review every proposed change.

1

Open a folder

Pick any local project. ShadRox builds a compact repo map and loads your rules automatically.

2

Ask, then review

Chat, press Ctrl+K or run an agent. Every proposed change shows up as a diff first — you accept or reject.

3

Run & commit

Preview it live, test in the terminal, and commit with an AI-written message right inside the app.

The agent

An AI that shows its work.

Bounded, reviewable and honest about its limits.

Reads first.
Then proposes.

The agent reads your project — files, search, diagnostics, Git — and proposes changes as diffs you accept or reject. Requests can include a compact repo map so it understands the codebase before touching anything.

  • Read-only tools: list, read, search, diagnostics, Git, outlines
  • Five tool rounds by default, with up to six calls per round
  • Edits go through a patch → review → apply pipeline
  • Unsafe edits are held for review, never silently written

Plan. Patch.
Verify. Repair.

Big goals become a task DAG of milestones. Each is verified with diagnostics, and failures get a repair brief. Still beta — review the results.

  • Verified with diagnostics and an optional approved command
  • Configurable repair attempts per milestone
  • Unrecoverable failure rolls back to the checkpoint

A small team,
with boundaries.

Why not just…

Aider and Cline are powerful.
They also need an IDE around them.

Same agent discipline and bring-your-own-key pricing — plus the editor, preview, Git UI and terminal the terminal-based tools leave out.

vs

Aider · Cline

Strong agents, no workspace. ShadRox adds the editor, live preview, Git tools and terminal around the same bounded, review-and-accept loop.

vs

Cloud AI editors

Requests go from your machine straight to the provider you configure — not through a middleman server. Point it at Ollama or LM Studio and nothing leaves your PC.

vs

Editor + plugin stacks

One native app instead of six extensions. Open a folder and the explorer, chat, preview and shell are already wired together.

Privacy

Local-first.
By design.

ShadRox edits real files on your disk. Only the prompt and context you choose go to the provider you picked. Your key never touches ShadRox servers.

Your computerfiles · key · rules
Your providerprompt + context
1

Files stay on your computer

No ShadRox cloud workspace and no project sync. The app opens the folder you pick.

2

Keys in OS-backed encrypted storage

Your provider key is sent with the request to the provider you configured — never to ShadRox.

3

Guarded commands

Risky delete-style commands (rm, del, Remove-Item…) hit a deny-list that forces an explicit approval dialog before anything runs.

4

Reviewable changes

Edits arrive as diffs. Unsafe patches are held for review instead of written in place.

Beta, and honest about it.

ShadRox is beta software, not a mature replacement for a general-purpose IDE. Agent output and model-generated edits can be incorrect, so review changes and keep backups for important work.

  • Review every AI diff and keep Git or backups for important work
  • Google sign-in is required to enter the app
  • Agent, autonomous run, team, plugin, and automation features are evolving
  • Preview support depends on your project and installed runtimes
  • Plan and credit-meter screens are previews; public payments are not enabled
