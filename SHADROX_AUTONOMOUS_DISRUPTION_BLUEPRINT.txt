1. THE CORE THESIS: WHY THE CURRENT INDUSTRY GIANTS ARE VULNERABLE
--------------------------------------------------------------------------------

Today's AI coding ecosystem is dominated by two flawed paradigms:

1. THE CLOUD-CONTAINER TRAP (Devin, Replit Agent):
   - Flaws: Spinning up remote AWS/GCP VMs for every user is wildly expensive
     ($200-$500/month subscriptions). It isolates the user from their actual local
     environment, SSH keys, hardware, local databases, and native device tooling.
     It suffers from network lag and major enterprise privacy/compliance blocks.
   
2. THE SIMPLE INLINE-COMPLETION TRAP (Cursor, VS Code Copilot, Trae):
   - Flaws: They act primarily as "smart text inserters" in single-turn or limited
     multi-turn chat. When an edit introduces type errors, runtime crashes, or CSS
     breakages, the user must act as the manual debugger. There is no true
     autonomous closed-loop verification.

WHERE SHADROX CAN DESTROY BOTH:
ShadRox already possesses the exact architectural primitives that neither Devin
nor Cursor has simultaneously:
- A real native Electron desktop core with local OS access, native PTY shells,
  and filesystem transactions.
- A worker-backed TypeScript Language Service running directly on the machine.
- An in-browser / native preview engine with error bridges and DOM click-to-source.
- Strict SEARCH/REPLACE transactional patch engine with syntax verification.
- 100% BYOK privacy where source code NEVER leaves the user's local disk.

If we connect these local primitives into a Self-Refining Autonomous Loop,
ShadRox becomes a tool that works autonomously on your real local repo, tests
itself, fixes its own errors, visually verifies UI, and costs $0 in platform fees.

--------------------------------------------------------------------------------
PILLAR 1: THE TRIPLE-FEEDBACK CLOSED LOOP (THE SENSORY SYSTEM)
--------------------------------------------------------------------------------
An autonomous agent is only as good as its feedback loop. Devin uses a remote
browser and remote terminal. Cursor uses language server diagnostics.
ShadRox must unite THREE concurrent local sensory streams into a single loop:

  +-----------------------------------------------------------------------+
  |                             USER GOAL                                 |
  +-----------------------------------------------------------------------+
                                     |
                                     v
  +-----------------------------------------------------------------------+
  |                      AGENT ORCHESTRATOR (DAG)                         |
  +-----------------------------------------------------------------------+
                                     |
                                     v
  +-----------------------------------------------------------------------+
  |              PATCH ENGINE (Multi-file SEARCH/REPLACE)                 |
  +-----------------------------------------------------------------------+
                                     |
                                     v
          +--------------------------+--------------------------+
          |                          |                          |
          v                          v                          v
   [ FEEDBACK 1 ]             [ FEEDBACK 2 ]             [ FEEDBACK 3 ]
  Static AST / Types       Sandbox Runtime Logs       Visual UI Perception
  - TS Worker Diagnostics   - Preview Error Bridge    - Headless Chromium
  - change-verify.cjs       - Terminal exit codes       Canvas Screenshot
  - Unresolved imports      - Console logs/warnings   - Layout & styling
  - Syntax check            - Network 404/500s          diff inspection
          |                          |                          |
          +--------------------------+--------------------------+
                                     |
                                     v
                      Is there any error or failure?
                               /           \
                             YES            NO
                             /                \
                            v                  v
                 [ AUTONOMOUS REPAIR ]       [ COMMIT TO DISK ]
                 - Inject missing imports    - Atomic transaction write
                 - Micro-patch errors        - Create checkpoint
                 - Retry with stacktrace     - Notify user with summary

Detailed Implementation of the 3 Streams:

1. Static AST Stream (Zero-Cost Instant Check):
   - Before any patch is committed to disk, `electron/change-verify.cjs` parses
     syntax.
   - The TS worker (`electron/ts-service.cjs`) compares diagnostic snapshots.
   - If TS2304 ("Cannot find name") occurs, `autoFix.ts` inserts the import
     deterministically (0 AI tokens spent).
   - If other diagnostics fail, the raw errors (file, line, code, message) are fed
     back into the model automatically with instruction: "Fix these exact
     diagnostics without altering surrounding logic."

2. Runtime Log Stream (Active Execution Check):
   - When a web app is previewed, `PREVIEW_ERROR_BRIDGE` streams window errors,
     unhandled promise rejections, and console errors directly into the agent.
   - For backend/CLI tasks, the AI PTY tab runs test commands (`npm test`,
     `pytest`, `cargo test`) and pipes stderr and non-zero exit codes directly
     into the agent's context.

3. Visual UI Perception Stream (The Visual Eye):
   - Electron captures the preview webContents as an off-screen image buffer.
   - A fast multimodal vision call (e.g. Gemini 2.5 Flash / 3.8 Flash) inspects
     the rendered UI: "Did the button overlap? Did the modal render blank? Is
     Tailwind CSS compiling?"
   - Catches subtle visual regressions that no compiler or unit test can detect.


--------------------------------------------------------------------------------
PILLAR 2: DUAL-SHELL AGENTIC ENVIRONMENT (NATIVE & SECURE)
--------------------------------------------------------------------------------
Industry flaw: Cursor requires manual terminal pasting or simple click-to-run.
Devin runs commands in a docker container that lacks user's local configs.

ShadRox's Style:
1. The AI Sanitized Execution Shell (`terminal-modes.cjs`):
   - Fully sandboxed from leaking API keys or secrets (all *KEY, *TOKEN, *AUTH
     environment variables stripped).
   - The agent can autonomously execute:
     * Package installs (`npm install`, `pip install`, `cargo add`)
     * Test runners (`npm test`, `vitest`, `playwright`)
     * Linting and formatting tools (`eslint --fix`, `prettier`)
     * Git branching and diff operations
2. Safe Execution Boundaries:
   - File modifications: Restricted strictly to the mounted workspace folder.
     Symlinks, directory traversal (`..`), and absolute paths outside the root
     are blocked at the OS layer (`electron/desktop-security.cjs`).
   - Destructive operations (`rm -rf`, `git reset --hard`, `drop database`):
     Intercepted by a native confirmation heuristic before execution.


--------------------------------------------------------------------------------
PILLAR 3: AUTONOMOUS SUB-AGENT SPECIALIZATION (SWARM ARCHITECTURE)
--------------------------------------------------------------------------------
Instead of one giant prompt trying to do everything (which causes hallucinations
and truncation), ShadRox breaks complex tasks into specialized sub-agents that
collaborate locally:

1. ARCHITECT AGENT (Planner):
   - Analyzes user goal and builds a Directed Acyclic Graph (DAG) of steps.
   - Reads project structure, package.json, manifests, and database schemas.
   - Produces a plan with clear acceptance criteria for each milestone.

2. CODER AGENT (Builder):
   - Writes atomic SEARCH/REPLACE patches.
   - Scoped strictly to files relevant to the current milestone.
   - Enforces code conventions and patterns found in the workspace.

3. INSPECTOR AGENT (Reviewer & Tester):
   - Validates syntax, runs type checks, and triggers relevant test suites.
   - Dispatches error logs back to the Coder Agent with exact line diffs.
   - Refuses to advance the DAG until current milestone criteria are verified.

4. UI/UX CRITIC AGENT (Designer):
   - Evaluates preview DOM and screenshots.
   - Verifies responsiveness across Desktop, Tablet, and Mobile viewport modes.


--------------------------------------------------------------------------------
PILLAR 4: ZERO-COST LOCAL CONTEXT & SEMANTIC GRAPH (LOCAL BRAIN)
--------------------------------------------------------------------------------
Cursor and Devin charge heavy markups for their server-side codebase indexing.
ShadRox does this 100% locally on the user's machine:

1. Hybrid Retrieval Engine:
   - Lexical Search: BM25 index on declaration-level chunks (`src/lib/retrieval.ts`).
   - Semantic Embeddings: Install `@huggingface/transformers` with ONNX/WASM
     (`all-MiniLM-L6-v2`) to run embeddings completely in-memory on CPU/GPU.
   - Tree-Sitter AST Graph: Maps function call graphs, class inheritances,
     and exported symbol dependencies.
2. Codebase Map Generation:
   - Compact ~9,000 char high-density repo map (shallow paths, exported symbols).
   - The agent always knows where every component, utility, and route lives
     without burning millions of tokens reading entire files.
3. Persistent Workspace Memory:
   - Saves architectural decisions, project conventions, and user preferences
     in a `.shadrox/memory.json` file inside the workspace.
   - The agent remembers previous bug fixes and architectural rules across sessions.


--------------------------------------------------------------------------------
PILLAR 5: ATOMIC TRANSACTIONAL SAFETY & INSTANT TIME-TRAVEL
--------------------------------------------------------------------------------
The number one fear developers have with autonomous agents like Devin is:
"What if the agent makes 50 changes and ruins my entire working codebase?"

ShadRox solves this decisively with Transactional Git & In-Memory Checkpoints:
1. Pre-Execution Git Stash / Branch:
   - When an autonomous task begins, ShadRox silently records a git commit/stash
     or creates an isolated `shadrox/autonomous-<id>` branch.
2. In-Memory Transaction Staging:
   - Edits are staged in memory. If any step fails or is aborted by the user,
     `atomicApply.ts` rolls back every touched file to its exact pre-apply state.
3. Visual Time-Travel Slider:
   - Every single autonomous step creates a snapshot in the Checkpoint Timeline
     (`src/lib/timeline.ts`).
   - The developer can drag the slider back in time to inspect or restore any
     intermediate state with one click.

3. STEP-BY-STEP IMPLEMENTATION ROADMAP FOR SHADROX
--------------------------------------------------------------------------------

PHASE 1: THE REPAIR LOOP (FOUNDATION)
- Task: Wire the feedback from `electron/change-verify.cjs` and the TS worker
  directly into an automatic repair prompt.
- Behavior: When the user accepts an AI patch, if TypeScript errors are detected,
  ShadRox does not just show "Fix N type errors"—it automatically triggers the
  bounded fix loop up to 3 iterations until clean.

PHASE 2: REAL LOCAL EMBEDDINGS & AST GRAPH
- Task: Install `@huggingface/transformers` in `package.json` and wire
  `src/lib/localEmbeddings.ts` directly into the chat retrieval pipeline.
- Behavior: Instant hybrid semantic + lexical search across thousands of files
  running 100% offline on the user's CPU/GPU.

PHASE 3: AUTONOMOUS TASK RUNNER (GOAL-DRIVEN AGENT)
- Task: Create `src/lib/autonomous/orchestrator.ts`.
- Behavior: User gives high-level prompt: "Build an auth page with form validation
  and connect it to the router".
  - Step 1: Architect plans files to create/edit.
  - Step 2: Coder creates files.
  - Step 3: TypeScript Language Service compiles and verifies.
  - Step 4: Preview reloads and validates no runtime crashes.
  - Step 5: Commits to disk and notifies user.

PHASE 4: VISUAL PERCEPTION AGENT
- Task: Integrate Electron `capturePage()` with the preview pane.
- Behavior: Agent captures the rendered canvas, detects styling issues or
  missing images, and adjusts CSS/Tailwind classes autonomously.

PHASE 5: MULTI-FILE CODEBASE REFACTOR ENGINE
- Task: Full-repository symbol renaming and refactoring powered by the
  TypeScript Language Service (`ts:references`, `ts:rename`).
- Behavior: Safe, deterministic multi-file refactoring that updates imports,
  declarations, and call sites without hallucinations.
